# Bash

## 1. What it is

Bash is a **shell**: a program that reads commands, one per line, and runs other programs. A **script** is a text file of such commands, so that a person types `./scripts/up.sh` once instead of fifty commands. Bash is also a small programming language: it has variables, functions, `if`, loops and pipes.

## 2. Why this repository uses it

A few scripts start the stack and publish the build; the pipeline's own helper scripts (`publish.sh`, `test-summary.sh`) are Bash, run on the build agent, and are tested like code.

## 4. How it works underneath

- A script starts with a **shebang** line such as `#!/usr/bin/env bash`. The operating system reads it and starts that program with the file as input.
- Every command ends with an **exit code**, a number from 0 to 255. `0` means success, anything else means failure. `if`, `&&`, `||` and `until` all look at it.
- A **variable** is written `name=value` and read as `"${name}"`. Quotes stop Bash from splitting a value at spaces.
- `$(command)` runs the command and pastes its output in place. `|` (a **pipe**) sends one command's output into the next command's input.
- `source file` runs another file *inside the current shell*, so its functions and variables become available. That is how one `lib.sh` is shared.
- **Standard output** (fd 1) is the normal output; **standard error** (fd 2) is for messages. `>&2` sends output to standard error; `>/dev/null` throws it away; `2>&1` joins error into output.
- Bash does not stop on errors unless told to. The line `set -euo pipefail` tells it to: `-e` stop at the first failing command, `-u` treat an unset variable as an error, `-o pipefail` make a pipe fail when any part of it fails (not only the last).

## 5. Walkthrough of this repository's use

### The header every script shares
```bash
#!/usr/bin/env bash
set -euo pipefail
source "$(dirname "${BASH_SOURCE[0]}")/lib.sh"
```
`#!/usr/bin/env bash` finds `bash` on the `PATH`. `set -euo pipefail` is explained in section 4. `${BASH_SOURCE[0]}` is the path of the file being run; `dirname` cuts off the file name; `source` loads the helpers from `lib.sh`, so the script works from any current folder.

### The helpers in `scripts/lib.sh`
```bash
ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
log() { printf '[%s] %s
' "$(date +%H:%M:%S)" "$*" >&2; }
die() { log "error: $*"; exit 1; }
require() { local tool; for tool in "$@"; do command -v "${tool}" >/dev/null 2>&1 || die "${tool} is not installed (see the prerequisites in README.md)"; done; }
wait_for() {
  local description="$1" timeout="$2" waited=0
  shift 2
  until "$@" >/dev/null 2>&1; do
    if [ "${waited}" -ge "${timeout}" ]; then die "timed out after ${timeout}s waiting for ${description}"; fi
    sleep 1
    waited=$((waited + 1))
  done
  log "${description}: ok (${waited}s)"
}
```
`ROOT` is the repository folder (`cd` inside `$( )` is a sub-shell, so the caller's folder does not change). `log` prints a time-stamped line to **standard error** (`>&2`) so standard output stays clean. `die` logs and exits with 1. `require` checks each tool with `command -v`, which succeeds when the tool is on the `PATH`. `wait_for <description> <seconds> <command...>` runs the command every second until it succeeds (`"$@"` is the command after `shift 2` removed the first two arguments) and stops with a message after the timeout. The checked command is re-run on every poll, so it must be a command or function (not a `$(...)` evaluated once).

Now the pieces that are new here:

### `scripts/lib.sh`
```bash
if [ -f "${ROOT}/.env" ]; then
  set -a
  source "${ROOT}/.env"
  set +a
fi
```
`set -a` turns on **auto-export**: every variable assigned while it is on is exported to child processes. `source .env` therefore exports the three secrets. `set +a` turns it off. `CONTROLLER_PORT="${CONTROLLER_PORT:-18481}"` then defaults the ports.

### `scripts/init-env.sh`
```bash
umask 077
sed -e "s/^ADMIN_PASSWORD=.*/ADMIN_PASSWORD=$(openssl rand -hex 16)/" \
    -e "s/^PUBLISH_TOKEN=.*/PUBLISH_TOKEN=$(openssl rand -hex 24)/" "${ROOT}/.env.example" > "${ROOT}/.env"
```
`umask 077` makes new files readable only by their owner (a file created now has mode 600). `sed -e ... -e ...` applies two replacements to a copy of `.env.example`: it fills the two empty secrets with random hex strings. The values never appear in the script, in the repository or on the screen; `.env` is ignored by Git. If `.env` already exists the script stops, so a second `make up` keeps the same secrets.

### `scripts/up.sh`
```bash
"${ROOT}/scripts/init-env.sh"
source "$(dirname "${BASH_SOURCE[0]}")/lib.sh"      # read .env now that it exists
docker compose up --detach --build --wait --wait-timeout 600
"${ROOT}/scripts/seed-project.sh"
wait_for "the agent to be online" 180 bash -c "curl -fsS -u admin:\"\${ADMIN_PASSWORD}\" ${CONTROLLER_URL}/computer/docker-agent/api/json | grep -q '\"offline\":false'"
```
`docker compose up --detach --build --wait` builds the images, starts every service in the background and **waits until each service's health check passes** (up to 600 s). After seeding the repository the script waits for the agent to be online: `bash -c '...'` is the command `wait_for` re-runs each second; `curl -u admin:password` authenticates with the admin password from the environment; the controller's API says `"offline":false` when the agent is connected.

### `scripts/seed-project.sh`
```bash
snapshot="$(mktemp -d)"
trap 'rm -rf "${snapshot}"' EXIT
(cd "${ROOT}" && git ls-files --cached --others --exclude-standard -z | xargs -0 tar -cf -) | tar -xf - -C "${snapshot}"
```
Make a temporary folder (removed when the script ends, however it ends). `git ls-files --cached --others --exclude-standard -z` lists the files Git tracks **plus** new files that are not ignored, separated by NUL characters (`-z`, safe for odd file names); `xargs -0 tar -cf -` packs exactly those files into an archive on standard output; `tar -xf - -C "${snapshot}"` unpacks it into the temp folder. The result is a clean copy without `.venv`, `.env` or build output. The script then makes a one-commit repository there and **force-pushes** it to the Git server in the stack, which is the repository the Jenkins job builds.

### `scripts/lint-jenkinsfile.sh`
```bash
auth=(-u "admin:${ADMIN_PASSWORD:?run make up first}" -b "${jar}" -c "${jar}")
crumb="$(curl -fsS "${auth[@]}" "${CONTROLLER_URL}/crumbIssuer/api/json" | sed -E 's/.*"crumbRequestField":"([^"]+)".*"crumb":"([^"]+)".*/\1:\2/')"
result="$(curl -fsS "${auth[@]}" -H "${crumb}" -X POST --data-urlencode "jenkinsfile@${ROOT}/Jenkinsfile" "${CONTROLLER_URL}/pipeline-model-converter/validate")"
```
An **array** of curl options is reused. `-b/-c ${jar}` read and write a cookie file (Jenkins ties a CSRF *crumb* to the session). `sed -E` turns the JSON `{"crumbRequestField":"Jenkins-Crumb","crumb":"abc"}` into the header text `Jenkins-Crumb:abc`. The POST sends the Jenkinsfile (`--data-urlencode name@file`) to the declarative linter; the script succeeds only if the answer contains `successfully validated`.

### `pipeline/scripts/publish.sh`
```bash
set -euo pipefail
set +x
file="${1:?usage: publish.sh <file>}"
: "${TOKEN:?TOKEN must be set (bind the publish-token credential around this step)}"
response="$(printf 'Authorization: Bearer %s\n' "${TOKEN}" |
  curl --silent --show-error --fail-with-body --max-time 60 \
    --retry 3 --retry-delay 2 --retry-connrefused --retry-all-errors \
    --header @- --upload-file "${file}" "${url}/artifacts/${name}")" || { echo "publish: the store refused the upload" >&2; exit 1; }
```
`set +x` makes sure command tracing is off, so the token cannot be printed by a trace. `: "${TOKEN:?...}"` is the idiom "fail with this message if TOKEN is unset" (`:` does nothing). The token goes into a **header line sent through standard input** (`--header @-` means "read headers from stdin"), so it never appears on a command line, in `ps`, or in a trace. `--fail-with-body` fails on an HTTP error but still prints the answer; `--retry 3 --retry-delay 2 --retry-connrefused --retry-all-errors` retries a flaky upload; `--max-time 60` bounds it; `--upload-file` sends the file with HTTP PUT.

### `pipeline/scripts/test-summary.sh`
```bash
shopt -s nullglob
files=("${directory}"/TEST-*.xml)
shopt -u nullglob
...
header="$(grep -m1 -o '<testsuite [^>]*' "${file}")"
run=$((run + $(grep -o ' tests="[0-9]*"' <<<"${header}" | grep -o '[0-9]*')))
```
`shopt -s nullglob` makes a pattern with no match expand to nothing (instead of the pattern text), so an empty folder gives an empty array; it is switched off again right away. `grep -m1 -o '<testsuite [^>]*'` takes the first opening tag; `<<<"${header}"` feeds a string to `grep` (**here-string**); two `grep -o` calls pull out `tests="12"` and then `12`. `$(( ))` adds. The script prints totals and ends with `[ $((failed + errored)) -eq 0 ]`, so its exit status is 0 only when nothing failed.

### `agent/entrypoint.sh` (plain `sh`)
```sh
: "${ADMIN_USER:=admin}"
secret="$(curl -fsS -u "${ADMIN_USER}:${ADMIN_PASSWORD}" "${JENKINS_URL}/computer/${JENKINS_AGENT_NAME}/jenkins-agent.jnlp" 2>/dev/null |
    sed -n 's:.*<argument>\([0-9a-f]\{64\}\)</argument>.*:\1:p' | head -n 1 || true)"
unset ADMIN_PASSWORD
export JENKINS_SECRET="${secret}" JENKINS_WEB_SOCKET=true
exec /usr/local/bin/jenkins-agent
```
`: "${VAR:=default}"` assigns a default. The loop (not shown) waits until the controller offers a secret. `sed -n 's:...:...:p'` uses `:` as the delimiter (the pattern contains `/`) and prints only the matching 64-hex-character secret. `unset ADMIN_PASSWORD` removes the admin password from the environment before the agent starts. `exec` replaces the shell with the agent program.

## 7. Mistakes people make

- **Unquoted variables.** `rm -rf $dir/` with an empty `dir` is a disaster; `"${dir}"` and `${var:?message}` stop it. Every variable here is quoted.
- **Forgetting that `$(...)` is evaluated once.** `wait_for "x" 60 test "$(cmd)" = ok` runs `cmd` one time, before the loop starts, and then checks a frozen string. This repository wraps checks in functions so they run again on every poll.
- **Ignoring failures.** Without `set -e` a script keeps going after an error. Every script here starts with `set -euo pipefail`.
- **`cd` in a script that later uses relative paths.** The scripts compute `ROOT` once and use absolute paths.
- **Using Bash features in `sh`.** A script with `#!/bin/sh` runs in a smaller shell; `[[ ]]`, arrays and `${var,,}` are Bash only.

## 8. Check yourself

1. What does a shebang line do?
   *Answer:* It tells the operating system which program should run the file.
2. What do `set -e`, `-u` and `-o pipefail` each protect against?
   *Answer:* `-e`: carrying on after a failing command. `-u`: using a variable that was never set. `pipefail`: hiding a failure in the first part of a pipe.
3. Why is `"${name}"` safer than `$name`?
   *Answer:* The quotes keep a value with spaces or special characters as one word, and the braces mark exactly where the name ends.
4. What is the difference between running `./lib.sh` and `source lib.sh`?
   *Answer:* Running starts a new process whose variables vanish at its end; `source` runs the lines in the current shell, so its functions stay available.
5. What exit code means success?
   *Answer:* 0.
